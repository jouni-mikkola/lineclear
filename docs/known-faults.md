# Known faults of Shepherdr 2.0

The faults seen in Shepherdr 2.0 (commit `ebb17d5`) before the fork, each with how it shows, the workaround people use
on Shepherdr 2.0, and what the fork does. Each fault has a test (in `server/test/`, or the one named) that fails on `ebb17d5` and passes
on the fork. None needed a large rewrite, so none is in `backlog.md`. Faults of Lineclear's own rules (queued `after` tasks holding slots, a full reviewer asking the owner) are not Shepherdr 2.0's and are not listed. The run that shows each test failing on `ebb17d5` is in `docs/numbers.md` under L20.

## Where the list comes from

A fault is listed when Shepherdr 2.0 at `ebb17d5` shows it in one of three places: the five faults the step names, the October incident log of the machine that ran it (counts in the rows), and the stalls its users cured by hand before the fork (`docs/stalls.md`). A fault is listed only with a workaround people used and a test. Nothing in these places is left out for being hard: a fault that needed a large rewrite would be in `docs/backlog.md` with its reason, and none is. A fault found later is a new row, not a gap in this one.

Lineclear's start rule (`src/starts.ts`) stays as a backstop: a start counts only once its agent answered. One that did not after 2 minutes gets its brief nudge typed into its pane, after 4 a restart, after 6 it shows "start failed", never as waiting for you.

October's incident log also shows `conflicts with origin/main` at done (136 times). The fork already refuses such a merge and names the files, so no row is added. The unit failures, deploy restarts and stuck-deploy alerts there belong to other tools, not to Shepherdr 2.0.

## Stall class: head-of-line block across projects

| Fault | How it shows | Cure | Test |
| --- | --- | --- | --- |
| One check line for every project | A project's check waits on a lock that agents outside the line hold. As head it holds the line, and no merge of any other project passes for hours. | One check line per repo, so repos never block each other. The machine's limit stays the check slots, shared by every line. A project script keeps no global lock of its own: it wraps the heavy part in `lineclear slot` (said in the brief). A head with no CPU use for 15 minutes shows as stuck in `lineclear status` and on Home, with the lock or process it waits for. | `server/test/check-queue.test.ts`, `test/briefs.test.ts` |
